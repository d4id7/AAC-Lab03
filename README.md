## Исследование 1

`int number = 1`: `01-00-00-00`
`int number = 256`: `00-01-00-00`
`int number = 65536`: `00-00-01-00`

1. Потому что `int` всегда занимает `4 байта` в памяти, какое бы число в нём не хранилось
2. Значение `01` сдвигается ровно на `1 байт` вправо
3. Один байт может хранить значения максимум до `255`. Число `256` уже не помещается в первый байт, поэтому единица сдвигается во второй байт. Число 65536 — это `256*256`. Каждое умножение на `256` сдвигает значение еще на `1 байт`, поэтому единица переезжает уже в третий байт

## Исследование 2

`Little-endian: True`
`Байты числа: 78-56-34-12`
Они идут именно в таком порядке, потому что компьютер использует `little-endian` порядок хранения байтов, т.е. байты числа хранятся в обратном порядке (`12 34 56 78` -> `78 56 34 12`)

## Исследование 3

Количество символов и байтов отличается, потому что в современной кодировке `UTF-8` используется переменная длина кодирования.
В таблице `Unicode` английские буквы имеют маленькие кодовые номера и в `UTF-8` занимают `1 байт`. Русские буквы имеют бОльшие кодовые номера, поэтому для их кодирования требуется уже `2 байта`

## Исследование 5

Потому что байты — это не сами символы, а их закодированное представление. Кодировка (например, `UTF-8`) — это набор правил, по которым номер символа из таблицы `Unicode` переводится в последовательность байтов.
Чтобы обратно превратить байты в символы, компьютеру нужно знать, по каким правилам эти байты были записаны. Если указать другую кодировку, компьютер прочитает те же самые байты по другим правилам, извлечёт неверные номера из таблицы `Unicode`, и вместо осмысленного текста мы получим "кракозябры"
